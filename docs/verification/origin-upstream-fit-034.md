## Suggested sequence and product ideas

Integrate the locally verified #3004 persistence repair with its permanent proof before release. #2970 remains a high-priority pending probe-bound candidate; this report does not claim its implementation. Their final integration commits must be recorded separately from this static checkpoint. The next small candidates are #2968's model filter, #3006's Windows discovery, #2998's completed-root report and #3000's composer stacking; reproduce each on its actual path before deciding to patch it. #2966's partial-reply persistence deserves early data-loss verification, with graceful shutdown and restart rather than only a driver unit test.

For Origin's project model, the most useful feature package is **reliable project automations**: combine #2976's recorded skipped/superseded runs with the previously reviewed [#3038](https://github.com/milind-soni/OpenMausBot/pull/3038) deletion cleanup, [#3052](https://github.com/milind-soni/OpenMausBot/pull/3052) repeated-error notices and [#3039](https://github.com/milind-soni/OpenMausBot/pull/3039) event-trigger idea. Scope each run to its project Chief, authorized sender/machine and durable side-effect identity. The previous [#3024](https://github.com/milind-soni/OpenMausBot/pull/3024) automation UI recommendation remains deferred with its existing foundation requirements; this report does not reopen or claim adoption of those patches.

Two smaller ideas remain useful without upstream billing: **answer a Chief's choice in your own words** from #3002, and **open this computer's logs** from the previously reviewed [#3058](https://github.com/milind-soni/OpenMausBot/pull/3058). The latter must be a main-selected diagnostics directory, not a renderer-supplied path. Memory reliability from the existing [#3017](https://github.com/milind-soni/OpenMausBot/pull/3017) recommendation should keep bounded capture/cancellation separate from changes to batching or which short exchanges are remembered; project/member attribution is part of the retained data contract.

Origin's shared workspaces/projects, Chief hierarchy, sender-runs execution, member permissions and human-approved GitHub merges govern every adaptation. No vendor Cloud subscription, plan entitlement, automatic secret replication or aggregate release merge is recommended. The final integrated source, CI, native builds and public publication require later exact-source evidence; this checkpoint claims only the finite static review above.
