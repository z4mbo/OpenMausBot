## The observed failure and reproduced product bug

The retained diagnostic now establishes more than the earlier `last=null` observation: the renderer marked thread A current, its empty composer was disabled and busy, while the server selected thread B. Both server tasks were idle, had no start stamp and had no accepted messages. This is evidence of a conversation that never became ready to send; it provides no evidence of a provider dispatch or turn failure. The Windows daemon guard from 052 did not clear the Linux failure.

The diagnostic alone does not establish the underlying cause.
